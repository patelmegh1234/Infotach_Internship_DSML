# Bug Report

## Overview
This document tracks all bugs, issues, and defects found during development and testing of the Acousticspace project.

---

## Bug Report Format

| Field | Description |
|---|---|
| **ID** | Unique bug identifier (e.g. BUG-001) |
| **Title** | Short summary of the bug |
| **Severity** | Critical / High / Medium / Low |
| **Priority** | P1 / P2 / P3 / P4 |
| **Status** | Open / In Progress / Fixed / Closed / Won't Fix |
| **Module** | Affected component or module |
| **Reported By** | Name of the person who found the bug |
| **Date Reported** | Date the bug was logged |
| **Steps to Reproduce** | Exact steps to trigger the bug |
| **Expected Result** | What should happen |
| **Actual Result** | What actually happens |
| **Screenshots** | Link or reference to screenshots |
| **Fix Description** | How the bug was resolved (filled when fixed) |

## Severity Definitions

| Level | Description |
|---|---|
| **Critical** | System crash, data loss, or complete feature failure |
| **High** | Major feature broken with no workaround |
| **Medium** | Feature partially broken; workaround exists |
| **Low** | Minor UI/UX issue or cosmetic defect |

## Priority Definitions

| Level | Description |
|---|---|
| **P1** | Must be fixed immediately |
| **P2** | Fix in current sprint |
| **P3** | Fix in next sprint |
| **P4** | Fix when time allows |
